# 连续性与信息控制

连续性不是「不出错别字」，而是同一时刻的人物、事实、空间、伤势、资源和知情范围能够互相对上。作者底牌与读者已知必须分开。

## 一、四类信息不要混

| 层 | 内容 | 正文如何使用 |
|----|------|--------------|
| 作者底牌 | 最终真相、未公开身份、隐藏规则、未来反转 | 只用于允许它的规划；不直接交给正文或审校 |
| 已接受事实 | 已写并接受的公开事件与状态 | 作为当前正文的事实依据 |
| 当前单元合同 | 本阶段要发生、可揭示与禁止提前释放的内容 | 决定本次能走到哪里 |
| 方法知识 | 节奏、文风、题材技法 | 只指导表达，不创造 canon |

未接受候选属于草稿，不属于已发生事实。知识文章中的案例同样不是本书事实。

## 二、写前的状态快照

给当前单元建立一份简短快照：

- 时间点：故事第几天、距上一单元多久；
- 人物：谁在哪、公开身份是什么、身体与资源状态如何；
- 关系：当前信任、债务、冲突，不拿初设代替演变后的关系；
- 伏笔：哪些已埋、已推进、已回收；
- 知情边界：POV 知道什么、怀疑什么、完全不知道什么；
- 物件：关键证物、信物、武器、文件此刻在谁手里。

只取当前单元需要的内容。完整账本用于管理，不等于每次都该塞进模型上下文。

## 三、身份与时间

身份不是人物名后的永久标签。职务、机构、公开身份会随单元改变；应以当前单元生效的身份为准，而不是一直使用开卷身份。

- `canon/identity-timeline.yaml` 管身份时间段，正文不要提前穿成终局身份。
- `story_day` 表示当前故事日，`gap_from_prev` 表示与上一单元的间隔。
- 时间跳跃要在开场让读者感知；跨城、养伤、旅程和调查都要给合理时间。
- 闪回必须有进入与返回标记；非闪回线不要无说明倒流。
- 同一场戏中的动作顺序要符合空间：已经离开的人不能无交代继续在场发言。

## 四、POV 知情边界

写每个关键判断前问：他凭什么知道？

允许的依据包括亲眼所见、可信或不完全可信的转述、已获得的材料、符合能力的推断。推断要有不确定性，不能把猜测写成作者认证。

| 问题 | 修正 |
|------|------|
| 主角准确说出反派秘密 | 改为可观察异常 + 有限推断，或先安排信息来源 |
| 角色响应尚未发生的消息 | 调整场景顺序，或补上传递过程 |
| 叙述者提前确认后文反转 | 保留现象与误判，删除全知认证 |
| 为悬念故意藏 POV 已明确看见的东西 | 换成合理注意焦点，不欺骗读者 |
| 配角像读过人物卡一样理解主角 | 只写他根据公开行为能形成的判断 |

## 五、伏笔与揭示

每条重要伏笔至少有：ID、公开内容、埋点、计划回收位置、当前状态。作者侧真相另存，不写进读者账。

一次有效揭示应同时满足：

1. 新信息改变读者或角色对旧事件的理解；
2. 关键依据在前文出现过，而不是揭晓时才补；
3. 揭示发生在当前合同允许的范围；
4. 揭示后产生行动或关系后果，不是只发一段说明。

「下一钩」可以制造期待，但不能成为提前泄漏的真相句。

## 六、接受后的连续性复核

- 章范围完整，没有漏章或把下一单元事件提前写完；
- 章间位置、时间、伤势、道具和服装连续；
- `state_deltas` 只写本单元真正发生的变化；
- 摘要与公开事实不含只有作者知道的底牌；
- 新角色、新规则、新能力已明确是候选设定还是正式采用；
- 下一单元能承接本次钩子，不需要假装它没发生。

## Checklist

- [ ] 当前人物身份、位置与状态来自正确时间点
- [ ] POV 的关键认知都有来源，没有全知泄漏
- [ ] 伏笔揭示公平且在允许范围内
- [ ] 候选、知识与作者底牌未污染公开事实
- [ ] 接受后账本能让下一单元从正确状态继续
