# 连续性与信息控制

连续性不是「不出错别字」，而是同一时刻的人物、事实、空间、伤势、资源和知情范围能互相对上。作者底牌与读者已知必须分开。

## 一、四类信息不要混

| 层 | 内容 | 正文如何使用 |
|----|------|--------------|
| 作者底牌 | 最终真相、未公开身份、隐藏规则、未来反转 | 只用于允许它的规划，不交给正文或审校 |
| 已接受事实 | 已写并接受的公开事件与状态 | 作为当前正文的事实依据 |
| 当前单元合同 | 本阶段要发生、可揭示、禁止提前释放的内容 | 决定本次能走到哪里 |
| 方法知识 | 节奏、文风、题材技法 | 只指导表达，不创造 canon |

未接受候选是草稿，不属于已发生事实。知识文章里的案例同样不是本书事实。

## 二、写前的状态快照

只取当前单元需要的内容（完整账本用于管理，不等于每次塞进上下文）：

- **时间**：故事第几天、距上一单元多久。
- **人物**：谁在哪、公开身份、身体与资源状态。
- **关系**：当前信任、债务、冲突，不拿初设代替演变后的关系。
- **伏笔**：哪些已埋、已推进、已回收。
- **知情边界**：POV 知道什么、怀疑什么、完全不知道什么。
- **物件**：关键证物、信物、武器、文件此刻在谁手里。

## 三、身份与时间

身份不是人物名后的永久标签。职务、机构、公开身份会随单元改变，以当前单元生效的身份为准，不提前穿成终局身份；`canon/identity-timeline.yaml` 管身份时间段。

- `story_day` 是当前故事日；`gap_days` 是与上一单元的最少间隔天数（整数）；`gap_from_prev` 是给写作者的承接说明，写成一句人话（如「隔天清晨，上一案卷宗已归档」），不写成数字。
- 时间跳跃要在开场让读者感知；跨城、养伤、旅程和调查都要给合理时间。
- 闪回必须有进入与返回标记；非闪回线不要无说明倒流。同一场戏的动作顺序要符合空间：已离开的人不能无交代继续在场发言。场面 `when`（故事时）与 `where`（地点）分列，并与人物卡位置栏一致。

## 四、POV 知情边界

写每个关键判断前问：他凭什么知道？允许的依据：亲眼所见、可信或不完全可信的转述、已获得的材料、符合能力的推断。推断要有不确定性，不能把猜测写成作者认证。

| 问题 | 修正 |
|------|------|
| 主角准确说出反派秘密 | 改为可观察异常 + 有限推断，或先安排信息来源 |
| 角色响应尚未发生的消息 | 调整场景顺序，或补上传递过程 |
| 叙述者提前确认后文反转 | 保留现象与误判，删除全知认证 |
| 为悬念故意藏 POV 已明确看见的东西 | 换成合理注意焦点，不欺骗读者 |
| 配角像读过人物卡一样理解主角 | 只写他根据公开行为能形成的判断 |

## 五、伏笔与揭示

伏笔是带稳定 ID 的实体，与人物卡同级，登记在 `canon/foreshadow-schedule.md`。每条至少要有：ID、内容、类型（物件/信息/关系/承诺/疑点）、埋点位置、计划回收位置、当前状态。

位置三级细化：总纲定卷（`plant_volume` / `payoff_volume`），卷纲定单元（`plant_unit` / `payoff_unit`），细纲定章（`chapters[].plant / payoff`）。每层只能细化，不能改写父层已定的位置。

**信息类伏笔就是揭示**：它回答「读者何时可以知道某个秘密」。「能不能说」和「该不该埋」是同一张表的两个读法。

写作时只有两类条目进入上下文：

- 本章 `plant` / `payoff` 点名的：给内容；回收时额外给「读者应得到什么」。
- 已埋未收的：只给 ID、内容与埋点位置，**不给回收摘要**——那是结局。

未到回收点的伏笔不得提前回收，也不得在铺垫里写出它的答案。

一次有效揭示应同时满足：新信息改变读者或角色对旧事件的理解；关键依据在前文出现过；发生在当前合同允许的范围；揭示后产生行动或关系后果，而不是只发一段说明。

「下一钩」可以制造期待，但不能成为提前泄漏的真相句。

## 六、接受后的连续性复核

- 章范围完整，没有漏章或把下一单元事件提前写完。
- 章间位置、时间、伤势、道具和服装连续。
- `state_deltas` 只写本单元真正发生的变化，字段名须在词表内（`role_title/location/health/resources/goal/knows/relation/life`）。
- 字段失效要写显式终值（伤好了写「已愈」）。账本每段是全量快照，没写终值的字段会一路被带着走——实测曾有一条伤势跨 6 个单元、63 个故事日，写作包一直把它当成「当前身体状况」。
- 会失效的字段（身体/位置/资源/关系/生命）连续三个单元没被刷新，审校会提示「可能已过期」，连续性块里也会标注「记于 N 个单元前」；看到就要判断该写终值还是真的没变。
- `life` 单向：alive → missing → dead；死者在后续单元不得再出场。
- 摘要与公开事实不含只有作者知道的底牌。
- 新角色、新规则、新能力已明确是候选设定还是正式采用。
- 下一单元能承接本次钩子，不需要假装它没发生。
