# 创作工作流与候选接受

把「总纲 → 卷纲 → 单元细纲 → 正文 → 审校 → 接受定稿」当作一条单向生产链。知识文章只提供方法；当前书籍文件提供事实；候选必须经作者接受才能成为正式内容。

## 一、各阶段只交自己的产物

| 阶段 | 该做什么 | 不该做什么 |
|------|----------|------------|
| 立项 / 重新立项 | 读者承诺、全书总纲、人物、世界、金手指、揭示计划、风格与作者底牌 | 写卷纲、单元 scenes 或正文 |
| 卷纲 | 本卷目标、人物、单元索引、卷末终局边界 | 改全书事实、写每章细节 |
| 单元细纲 | 欲望、阻碍、选择、兑现、在场人物、POV、scenes、状态变化、信息控制、时间与下一钩 | 另改卷纲功能、提前揭底 |
| 正文 | 按单元合同写全部指定章节，让场面与选择落地 | 用知识文章替换书籍事实、漏章 |
| 审校 | 提供有证据的问题、严重级别与修改方向 | 借审稿偷偷重写整本书 |
| 定向修订 | 只修指定问题，保留已经成立的部分 | 自由发挥、顺手改变无关事实 |
| 接受 | 作者确认候选，写入目标文件并推进流程 | 把生成成功误当成已接受 |

## 二、动笔前的最小合同

一个可写单元至少能回答：

1. **desire**：谁此刻要什么？
2. **obstacle**：什么具体力量阻止他？
3. **choice**：他作出什么不可替代的选择？
4. **payoff**：本单元兑现什么，付出什么代价？
5. **on_stage / pov**：谁在场，读者贴着谁的感知？
6. **scenes**：哪些场面让冲突变化，而不是只换地点？
7. **stateDeltas**：结尾相较开场，事实、身份、资源、关系或伏笔改变了什么？
8. **nextHook**：结尾哪个具体事件使读者想翻页？
9. **storyDay / gapFromPrev**：故事时间怎么接上前文？
10. **infoControl**：本场能透露什么，不能透露什么？

缺少的是「合同」，先补细纲；缺少的是「表现力」，才写正文或润色。不要用扩写掩盖没有冲突的问题。

## 三、场面怎么承载情节

每个 scene 尽量能指认：

- `who / where / when`：谁在哪、故事时间是什么；
- `beat`：发生了什么可观察的动作；
- `must_land`：读者离场前必须收到的信息或变化；
- 情绪变化、读者效果、潜台词（需要时写 `emotional_beat / reader_effect / subtext`）。

同章至少两个场面时，第二场应由第一场的结果驱动，不是另起一则小故事。纯功能路人写在场面描述里；反复出场、影响主线的角色才进入人物管理。

## 四、知识怎么用才不污染正文

1. 先看上下文预览：事实是否来自当前书籍，人物是否是本单元在场人物。
2. 只勾选解决当前问题的知识，例如「开篇慢」选节奏，「线索不公平」选推理。
3. 知识里的示例、人名、数字、程序、题材标签都不是本书事实，除非书籍文件明确采用。
4. 多篇规则冲突时：当前书籍合同 > 本书风格指纹 > 当前题材专项 > 通用建议。
5. 附加越多不一定越好；重复或互相争抢的指令会降低遵从度。

## 五、状态与边界

正式流程为 `proposed → accepted → drafted → reviewed`。生成候选不会自动修改 canon 或正文；接受操作才写盘。

- **候选开放**不代表它已经是事实，后续规划不得提前使用。
- **重写人物或设定**只写目标文件；附带的总纲与关系依据是只读参考。
- **卷末边界**规定本卷最多走到哪，下一卷钩子不能偷跑终局底牌。
- **重新立项**不是续写：需要保留的精修文件应在接受前明确选择。

## 六、一次生成失败时怎么修

先区分失败类型，再决定是否重新调用：

| 症状 | 首选处理 |
|------|----------|
| JSON 缺字段、章数不对 | 修复输出结构，不重写故事 |
| 欲望、冲突或兑现不成立 | 回改细纲，不直接扩写 |
| 人物说错话、知道不该知道的事 | 对照人物卡、POV 和揭示约束定向修 |
| 单章过短、模板词过多 | 只修该章，保留其他已通过章节 |
| 上下文带入未来秘密 | 停止接受，修正信息边界后重做 |
| 故事本身满意但短 | 判断是否真的缺戏；完整而短不应硬灌水 |

## Checklist

- [ ] 当前任务与阶段匹配，没有让立项代写正文
- [ ] 单元最小合同可回答，scenes 能推动选择
- [ ] 知识只作方法参考，未提供未经采用的新事实
- [ ] 候选与正式文件已区分，接受前已核对目标路径与基准内容
- [ ] 失败按类型定向处理，不用整本重写解决局部问题
