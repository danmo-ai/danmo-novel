# 创作工作流与候选接受

把「总纲 → 卷纲 → 单元细纲 → 正文 → 审校 → 接受定稿」当作一条单向生产链。知识文章只提供方法；当前书籍文件提供事实；候选必须经作者接受才能成为正式内容。

## 一、阶段与知识地图

每个阶段只挂自己那一组文章。同一主题只有一篇负责，其余篇在需要时用标题引用，不重写规则。

| 阶段 | 交什么 | 该阶段可挂的知识 |
|------|--------|------------------|
| 立项 | 读者承诺、总纲、人物、世界、金手指、揭示计划、风格与底牌 | 节奏与结构（开篇）、人设设计、世界观与金手指、强约束、连续性与信息控制、推理公平与线索设计、本题材篇 |
| 卷纲 | 本卷目标、人物、单元索引、卷末终局边界 | 节奏与结构（锁卷与八节点）、爽点与追读（密度）、强约束（期待债） |
| 单元细纲 | 欲望、阻碍、选择、兑现、在场人物、POV、scenes、状态变化、信息控制、时间、下一钩 | 爽点与追读（钩子）、情绪与场景、推理公平与线索设计、人物与群像落笔、本题材篇 |
| 单元正文 | 按单元合同写全部指定章节 | 节奏与结构（章内节奏）、爽点与追读（段落钩）、文风与去 AI 味、情绪与场景、设定随行动带出、人物与群像落笔、本题材篇；刑侦探案另加刑侦人味文风 |
| 审校 | 有证据的问题、严重级别、修改方向 | 审校规则（默认注入）、强约束、连续性与信息控制、推理公平、定向修订、本题材红线 |
| 设定重写 | 只写目标设定文件 | 人设设计、世界观与金手指、文风与去 AI 味 |

追加文章不是越多越好。同一主题勾两篇会让两条规则互相争抢注意力：开篇慢只勾「节奏与结构」，不要再叠题材篇和平台篇。

## 二、每个阶段只交自己的产物

| 阶段 | 不该做什么 |
|------|------------|
| 立项 | 写卷纲、单元 scenes 或正文 |
| 卷纲 | 改全书事实、写每章细节 |
| 单元细纲 | 另改卷纲功能、提前揭底 |
| 正文 | 用知识文章替换书籍事实、漏章 |
| 审校 | 借审稿偷偷重写整本书 |
| 定向修订 | 自由发挥、顺手改变无关事实 |
| 接受 | 把生成成功误当成已接受 |

## 三、动笔前的最小合同

一个可写单元至少能回答：desire（谁要什么）、obstacle（具体什么力量阻止）、choice（什么不可替代的选择）、payoff（兑现什么、付什么代价）、on_stage / pov、scenes（哪些场面让冲突变化）、stateDeltas（相较开场改变了什么）、nextHook（哪个具体事件让人翻页）、storyDay / gapFromPrev、infoControl（能透露什么、不能透露什么）。

缺的是合同，先补细纲；缺的是表现力，才写正文或润色。不要用扩写掩盖没有冲突的问题。

## 四、场面怎么承载情节

每个 scene 尽量能指认 `who / where / when`（谁在哪、故事时间）、`beat`（可观察的动作）、`must_land`（离场前必须收到的信息或变化），需要时补 `emotional_beat / reader_effect / subtext`（写法见「情绪与场景」）。

同章至少两个场面时，第二场应由第一场的结果驱动，不是另起一则小故事。纯功能路人写在场面描述里；反复出场、影响主线的角色才进入人物管理。

## 五、知识怎么用才不污染正文

1. 先看上下文预览：事实是否来自当前书籍，人物是否是本单元在场人物。
2. 只勾选解决当前问题的知识：开篇慢选节奏，线索不公平选推理。
3. 知识里的示例、人名、数字、程序、题材标签都不是本书事实，除非书籍文件明确采用。
4. 规则冲突时：当前书籍合同 > 本书风格指纹 > 当前题材专项 > 通用建议。
5. 重复或互相争抢的指令会降低遵从度，宁可少勾一篇。

## 六、状态与边界

正式流程为 `proposed → accepted → drafted → reviewed`。生成候选不会自动修改 canon 或正文；接受操作才写盘。

- 候选开放不代表它已是事实，后续规划不得提前使用。
- 重写人物或设定只写目标文件；附带的总纲与关系依据是只读参考。
- 卷末边界规定本卷最多走到哪；下一卷钩子不能偷跑终局底牌。
- 重新立项不是续写：需要保留的精修文件应在接受前明确选择。

## 七、一次生成失败时怎么修

| 症状 | 首选处理 |
|------|----------|
| JSON 缺字段、章数不对 | 修复输出结构，不重写故事 |
| 欲望、冲突或兑现不成立 | 回改细纲，不直接扩写 |
| 人物说错话、知道不该知道的事 | 对照人物卡、POV 与揭示约束定向修 |
| 单章过短、模板词过多 | 只修该章，保留其他已通过章节 |
| 上下文带入未来秘密 | 停止接受，修正信息边界后重做 |
| 故事满意但短 | 判断是否真缺戏；完整而短不灌水 |

## Checklist

- [ ] 当前任务与阶段匹配，没有让立项代写正文
- [ ] 只挂了本阶段该挂的文章，没有同主题重复勾选
- [ ] 单元最小合同可回答，scenes 能推动选择
- [ ] 知识只作方法参考，未提供未经采用的新事实
- [ ] 候选与正式文件已区分，接受前已核对目标路径与基准内容
- [ ] 失败按类型定向处理，不用整本重写解决局部问题
